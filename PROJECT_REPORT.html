Cloud Computing Project Report

Cloud-Based Video Fingerprint Collection System

A dashcam proof of concept for an insurance company using real-time cryptographic frame fingerprints, database-backed video evidence, and customer-scoped integrity analysis.

Project workspace: CloudVideoFingerprint
Technology: Python, FastAPI, browser MediaRecorder, Web Crypto SHA-256, SQLite fallback, Supabase PostgreSQL integration
Date: September 2026

1. Executive Summary

This project implements a cloud-ready evidence collection system for an insurance company. A customer enters a unique ID and uses a browser camera as a dashcam. Raw video remains local while recording. Frame fingerprints are generated locally and transmitted in real time. When recording stops, the completed video and its fingerprint metadata are stored in the database and linked to the customer ID.

An insurance user can filter saved media by customer, select a specific video, and run an integrity check. The system calculates a complete-file SHA-256 digest, analyzes frame fingerprints, detects duplicate uploads, and detects frame reuse across different videos.

4. Customer Workflow

  1. Enter a unique customer ID.
  2. Enable the camera and start local recording.
  3. During recording, the browser samples frames and calculates SHA-256 fingerprints.
  4. Fingerprints are transmitted to the real-time stream while raw video remains local.
  5. When the customer stops recording, the final video is stored with its customer ID and fingerprints.
  6. Customers may also choose a local photo/video and upload it directly.

5. Insurance Workflow

  1. Open the Insurance Dashboard.
  2. Filter saved media by customer ID.
  3. Review the video list, filename, type, fingerprint count, and timestamp.
  4. Click Check integrity for one specific video.
  5. Review the SHA-256 file digest, integrity percentage, verified/unverified frame counts, and frame-by-frame results.
  6. Investigate re-upload warnings and frame-overlap warnings when displayed.

6. Integrity and Cryptographic Analysis

The system uses SHA-256 for complete media files and sampled frames. A complete-file digest verifies whether stored bytes match the original stored reference. Frame fingerprints are compared with previous videos for the same customer.

  • Integrity percentage: verified frames divided by analyzed frames multiplied by 100.
  • Duplicate upload: same customer ID and same complete-file SHA-256.
  • Frame overlap: a frame fingerprint found in another video for the same customer.
  • Unverified frame: a duplicate or overlapping frame requiring insurance review.
The system deliberately uses the neutral terms verified and unverified. An unverified frame is flagged for review; it is not automatically declared fraudulent.

7. Database and Security

The Supabase schema creates fingerprints, live_fingerprints, and media_files tables. Row Level Security is enabled, with service-role policies for the server-side API. The service-role key is loaded from .env and must never be exposed to browser code or committed to source control.

For local demonstrations, SQLite provides an offline fallback. For cloud evaluation, the schema must be executed in Supabase and the environment must report storage_backend: Supabase.
